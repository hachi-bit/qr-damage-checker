# qr-damage-checker

QRコードが写った画像やカメラ映像から、QRコードの規格情報と**破損率**を調べるブラウザ用ツールです。
画像はブラウザの中だけで処理され、どこにも送信されません。

## できること

- 画像ファイルの選択、ドラッグ＆ドロップ、クリップボードからの貼り付けで解析
- スマートフォンなどのカメラでリアルタイムに読み取り
- 1枚の画像に写った複数のQRコードをまとめて解析し、画像上に番号付きの枠で表示
- 壊れているマスを、QRの拡大図と写真の上に色付きで表示（通常のQRコード モデル2のみ）
- 対応規格: QRコード（モデル2）、マイクロQRコード、rMQRコード（旧規格のモデル1も判別する作りですが、手元に見本がなく未検証です）

表示する情報:

| 項目 | 内容 |
|---|---|
| 規格 | QRコード モデル1／モデル2、マイクロQR、rMQR |
| バージョン | 1〜40（マイクロQRは M1〜M4、rMQR は縦×横）とモジュール数 |
| 誤り訂正レベル | L（約7%）／M（約15%）／Q（約25%）／H（約30%） |
| マスクパターン | 0〜7 |
| 破損率 | 誤り訂正能力をどれだけ使い切ったか（0%〜100%、超えると読み取り不可） |
| コードワード数 | 総数と、そのうち誤り訂正用の数 |
| 内容 | 読み取った文字列 |

## 破損率の定義

QRコードのデータは複数のブロックに分かれ、ブロックごとにリード・ソロモン符号で誤り訂正されます。
どれか1つのブロックでも訂正の上限を超えると読めなくなるため、このツールでは**最も傷んだブロック**について

```
破損率 = 訂正したコードワード数 ÷ 訂正できるコードワード数の上限
```

を表示します。0% は訂正なしで読めた状態、100% は上限ちょうど（これ以上傷むと読めない）状態です。
QRコードは見つかったが訂正しきれない場合は「読み取り不可」と表示します。

### 計算方法

読み取りには [zxing-wasm](https://github.com/Sec-ant/zxing-wasm)（[zxing-cpp](https://github.com/zxing-cpp/zxing-cpp) の WebAssembly 版）を使っています。
zxing-cpp は読み取り結果に `UEC`（unused error correction: 未使用の訂正余力）を返します。これは各ブロックの
`1 − 使った誤り訂正コードワード数 ÷ 誤り訂正コードワード数` の最小値です（zxing-cpp の `QRDecoder.cpp` / `ReedSolomon.cpp`）。

誤り1つの訂正には誤り訂正コードワードを2つ使うので、規格書のブロック構成表（`js/tables.js`）と組み合わせて、
最も傷んだブロックで訂正したコードワード数を求めています。`UEC` は小数2桁ですが、1ブロックの誤り訂正コードワード数は最大30なので、整数に丸めれば正確に戻せます。
ブロック構成表を持っていない rMQR とモデル1は `1 − UEC` をそのまま破損率として表示します。

### 破損箇所の表示

読み取りライブラリは「写ったマスの白黒」を返しますが、どこが壊れていたかは返しません。そこで `js/damagemap.js` で次のように求めています。

1. 写ったマスからマスクを外してコードワードに戻し、ブロックごとに自前のリード・ソロモン復号（`js/reedsolomon.js`）で誤りを訂正する
2. 訂正後のコードワードと、規格どおりの位置検出パターン・タイミングパターン・位置合わせパターン・形式情報・型番情報から「本来の模様」を作る
3. 写った模様と1マスずつ比べる

色の意味:

- 赤: データ部分の傷。破損率の計算に入ります。
- オレンジ: 位置検出パターンや形式情報など、データ以外の部分の傷。破損率には入りませんが、壊れると読み取りにくくなります。

「読み取り不可」のQRコードは本来の模様が分からないため表示できません。マイクロQRとrMQRはマスの並び方が違うため未対応です。

### 注意

- 写真のぼけ、ピントのずれ、照明の反射も「破損」として数えられます。印刷物そのものの傷み具合を見たいときは、正面から明るくピントを合わせて撮影してください。
- 訂正の上限は読み取りライブラリ（zxing-cpp）の能力に基づきます。規格では小さいバージョン（1-L など）で誤訂正防止のために訂正数を少なめに見積もる場合がありますが、このツールではライブラリが実際に訂正した値を使います。

## 使い方

GitHub Pages で公開したページを開くだけで使えます。カメラを使うには https で開く必要があります（GitHub Pages は https です）。

### GitHub Pages での公開手順

1. リポジトリの **Settings → Pages** を開く
2. **Source** を「Deploy from a branch」、ブランチを `main`、フォルダを `/ (root)` にして保存
3. 数分後に `https://hachi-bit.github.io/qr-damage-checker/` で公開されます

### 手元で動かす

ビルドは不要です。静的ファイルをそのまま配信します（`file://` で直接開くと WebAssembly を読み込めないため、簡易サーバーを使ってください）。

```sh
npm start            # http://localhost:8080 で起動
# または
python3 -m http.server 8080
```

### テスト

QRコードを実際に生成し、わざと壊して読み取らせ、訂正数や破損率が正しく出るかを確かめます。

```sh
npm install
npm test
```

## ファイル構成

```
index.html                 画面
css/style.css              見た目（ダークモード対応）
js/app.js                  画像・カメラの入力と結果の表示
js/analyze.js              読み取り結果から規格情報と破損率を組み立てる
js/damagemap.js            壊れているマスを探す
js/reedsolomon.js          リード・ソロモン復号（誤り位置を求める）
js/tables.js               誤り訂正ブロック構成表・位置合わせパターンの位置
vendor/zxing-wasm/         読み取りエンジン（zxing-wasm 3.1.5 のビルド済みファイル）
test/analyze.test.mjs      テスト
```
